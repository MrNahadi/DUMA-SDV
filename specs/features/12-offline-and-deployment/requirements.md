# 12 · Offline and deployment: requirements

Scope decision (2026-09-25, owner): **public deployment is skipped for now.** This phase delivers the offline build and the documented offline check. Publishing a public URL (brief §12, "A public URL loads the app") stays open for a later phase and is recorded in the roadmap.

## Offline

- **R1.** The production build is a PWA: a web app manifest (name Duma SDV, the brand mark icon, standalone display, the app's background and theme colours from the tokens) and a service worker generated by `vite-plugin-pwa` 1.3.0 (the approved dependency).
- **R2.** The service worker precaches every file the app needs: HTML, JS chunks (including the lazy 3D stage), CSS, fonts and icons. After one online load, a reload with the network off shows the full app, and the car can be powered on and driven.
- **R3.** Nothing is fetched from another origin at runtime (tech-stack.md, 3D: everything is local).
- **R4.** The build still works under a sub-path (`base: './'`), so the same `dist/` can later be served from any static host.
- **R5.** A new build replaces the old service worker on the next load (auto update), so a judge never runs a stale version after the team rebuilds.
- **R6.** The service worker is only registered in the production build, not in the dev server or in Vitest.

## Offline check

- **R7.** README documents the offline check for the venue laptop: build, preview, load once, turn off the network, reload, and run the guided demo. It also documents running from a clean checkout with no network after `npm ci`.
- **R8.** A Playwright test loads the app, waits for the service worker to control the page, switches the browser context offline, reloads, and powers the car on to READY with no console errors and no failed requests.
